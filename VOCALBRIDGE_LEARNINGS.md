| 2026-07-18T17:07Z | **IngestDO architecture — locked.** `VB debug stream → IngestDO (singleton, one subscription) → demux by session_id → CallDO (one per dispatch) → SSE → dashboard`. Rules: (1) **Employees/itineraries live in D1, not DOs** — "who is on flight A" is a `WHERE`, not a DO lookup. (2) **CallDO is the append-only event log** — order by a DO-assigned monotonic `seq++`, **not** by timestamp: `tool_call`/`tool_result` routinely collide at ms resolution and VB's clock is not yours. DOs are single-threaded so `seq` is free and correct. Zero-pad storage keys (`evt:00000042`) so lexicographic `storage.list()` is chronological; keep VB's `timestamp` as a display field only. (3) **SSE gives cursor-resume for free** — emit `id: <seq>`, browser auto-reconnects with `Last-Event-ID`, DO replays everything after that cursor then streams live. No custom diff protocol needed, and a dispatcher opening the screen mid-call gets full history, not just events from connect time. (4) WS-vs-SSE is two hops — WS (or polling) on ingest, SSE on egress; no conflict. Note SSE keeps the DO awake (hibernation is WebSocket-only). (5) **Post-processing MCP is the terminal write** — flips status to `RESOLVED` and stores the final transcript, guaranteeing closure even if the debug stream dropped mid-call. A debug channel is not a delivery-guaranteed transport; treat it as best-effort with a durable backstop. | Cloudflare DO/D1, `/api/v1/debug/*`, `--post-processing-mcp-url` |

| 2026-07-18T17:46Z | **IngestDO confirmed against Cloudflare docs — feasible, with one real gotcha and two refinements.** (1) **Gotcha: an outbound WebSocket keeps a DO alive for a maximum of 15 minutes**, after which it stops preventing eviction (the socket itself keeps working) and the normal 70–140s idle rule resumes. A singleton IngestDO holding one long-lived WS to VB *will* get evicted mid-demo if the room goes quiet. **Fix: a repeating alarm as reconnect watchdog** — `alarm()` has guaranteed at-least-once execution with exponential backoff (2s, up to six retries) and exposes `alarmInfo.retryCount`; alarms don't self-repeat, so re-arm each fire and make the handler idempotent. Cheap and it doubles as the liveness check the best-effort debug stream needs anyway. (2) **Refinement: use a SQLite-backed DO** (`new_sqlite_classes`, 10GB/object, `ctx.storage.sql`) — the event log is a table with `INTEGER PRIMARY KEY AUTOINCREMENT`, so `seq` is free and ordered without the zero-padded-key trick from the earlier entry; that entry's intent stands, the mechanism is simpler. SQLite is also the only backend on the Free plan. (3) **Refinement: dispatch is a plain `fetch()`, which never keeps a DO alive** — so fire it from the Queue consumer Worker, not from inside a DO expecting to stay warm. Confirmed as designed: hibernation is WebSocket-only, an open SSE response keeps the DO in memory (and billing duration), and Queues exposes `max_concurrency` as literally one config value alongside `max_retries` + `dead_letter_queue` (auto-created), `retry_delay`, and per-message `delaySeconds` — the fan-out guard is exactly as cheap as assumed. **Demo hazard: deploying new code disconnects every WebSocket and restarts every DO.** Do not push during the demo. | Cloudflare DO (lifecycle, alarms, SQLite storage), Queues |
